# Text-to-Widget System Spec
**Version:** 0.1  
**Target:** Agent handoff — implement this end to end

---

## Overview

A Swift browser (WKWebView-based) where the user types a natural language prompt and gets back a live, data-fetching widget rendered in HTML/JSX. The LLM acts as an orchestration agent: it selects data sources, builds a skill chain (a series of primitive fetch/parse/transform operations), and emits a widget config + skill chain JSON that the runtime executes.

---

## System Diagram

```
User Prompt (Swift UI)
        │
        ▼
  LLM Agent (Claude)
  ├── Reasons about data sources
  ├── Selects widget template type
  └── Emits: WidgetManifest (JSON)
        │
        ▼
  Skill Chain Executor (JS runtime in WKWebView)
  ├── Executes steps: fetch → parse → transform
  └── Produces: structured data object
        │
        ▼
  Widget Renderer (JSX/HTML in WKWebView)
  └── Renders template with live data
        │
        ▼
  Swift ↔ JS Bridge (WKScriptMessageHandler)
  └── Lifecycle: load, refresh, error, dismiss
```

## 1. Swift ↔ JS Bridge Contract

The browser hosts a WKWebView that loads a local `runtime.html` bundle. Communication is bidirectional.

### Swift → JS (evaluateJavaScript)

```swift
// Inject a widget manifest to render
bridge.send("renderWidget", payload: widgetManifest)

// Trigger a data refresh
bridge.send("refreshWidget", payload: ["id": widgetId])

// Resize container (WKWebView frame changed)
bridge.send("resize", payload: ["width": w, "height": h])
```

### JS → Swift (WKScriptMessageHandler, name: `widgetBridge`)

```javascript
window.webkit.messageHandlers.widgetBridge.postMessage({
  type: "ready",           // runtime loaded and initialized
  type: "dataLoaded",      // skill chain complete, widget rendering
  type: "error",           // unrecoverable error with message
  type: "heightChanged",   // widget content height changed (for scroll-free sizing)
  payload: { ... }
})
```

**Swift must handle all five message types.** Unknown types are silently ignored.

## 2. Widget Manifest (LLM Output Schema)

This is the single JSON object the LLM emits. It is the contract between LLM and runtime.

```typescript
interface WidgetManifest {
  id: string                  // uuid, generated by LLM
  version: "1"
  widgetType: WidgetType      // see §4
  config: WidgetConfig        // template-specific display config
  skillChain: SkillStep[]     // ordered execution plan
  returns: string             // which outputKey holds final data
  ttl: number                 // cache TTL in seconds (0 = no cache)
  prompt: string              // original user prompt, for display
}

type WidgetType =
  | "barChart"
  | "lineChart"
  | "statCard"
  | "table"
  | "list"
  | "text"
  | "priceCard"

interface SkillStep {
  step: number                // 1-indexed execution order
  skill: SkillName            // see §3
  params: Record<string, any> // may contain $refs (see §5.2)
  outputKey: string           // key in execution context
}
```

## 3. Primitive Skills Registry

All skills are pure functions. The executor calls them by name. **No skill has side effects beyond network I/O.**

```typescript
type SkillName =
  | "fetchUrl"
  | "parseHtml"
  | "parseJson"
  | "extractWithRegex"
  | "parseCsv"
  | "transform"
  | "filterSort"
  | "mergeArrays"
  | "computeStats"
```

### 3.1 fetchUrl

```
Fetches a URL and returns the response body as a string.

params:
  url:     string  (required)
  method:  "GET" | "POST"  (default: "GET")
  headers: object  (optional)
  body:    string  (optional, for POST)

returns: string (raw response body)

errors: throws on non-2xx status with { status, statusText }
```

> **Security note:** All fetches go through a Swift-side URL allowlist. The WKWebView content policy blocks direct `fetch()` calls to arbitrary origins. Instead, fetchUrl routes through a Swift WKURLSchemeHandler (`widget-fetch://`) that enforces the allowlist and injects CORS headers. The JS skill calls `widget-fetch://<encoded-url>` not the real URL directly.

### 3.2 parseHtml

```
Parses HTML and extracts elements using CSS selectors.

params:
  html:        string  (required)
  selector:    string  (required, CSS selector)
  attribute:   string  (optional — if set, returns attribute values)
  extractText: boolean (default: true — return textContent)
  limit:       number  (optional — max elements to return)

returns: string[]
```

### 3.3 parseJson

```
Parses a JSON string and extracts a value by path.

params:
  json: string  (required)
  path: string  (optional — dot/bracket notation: "data[0].price")

returns: any (the value at path, or full parsed object if no path)

notes:
  - Path supports: dot access, bracket index, wildcard [*]
  - Wildcard [*] maps over array and returns array of that field
  - Example: "prices[*][1]" → all second elements of prices array
```

### 3.4 extractWithRegex

```
Applies a regex pattern to a string.

params:
  text:    string  (required)
  pattern: string  (required, regex without delimiters)
  flags:   string  (default: "g")
  group:   number  (optional — capture group index, default: 0 = full match)

returns: string[]
```

### 3.5 parseCsv

```
Parses CSV text into an array of objects (or arrays).

params:
  csv:       string  (required)
  hasHeader: boolean (default: true)
  delimiter: string  (default: ",")

returns: object[] | string[][]
```

### 3.6 transform

```
Reshapes data using a field mapping spec.

params:
  data:    any     (required — object or array)
  mapping: object  (required — { outputField: "inputPath" })

notes:
  - mapping values use the same path notation as parseJson
  - If data is an array, mapping is applied per item
  - Literal values: prefix with "literal:" e.g. "literal:USD"
  - Arithmetic: prefix with "expr:" e.g. "expr:item.price * 1.1"
    (only +, -, *, / with numeric fields supported)

returns: object | object[]

example:
  data: [{ title: "BTC", last_price: 45000 }]
  mapping: { name: "title", price: "last_price", currency: "literal:USD" }
  → [{ name: "BTC", price: 45000, currency: "USD" }]
```

### 3.7 filterSort

```
Filters and/or sorts an array.

params:
  data:      array   (required)
  filter:    object  (optional — MongoDB-style operators)
  sortBy:    string  (optional — field path)
  ascending: boolean (default: true)
  limit:     number  (optional)

filter operators: $eq, $ne, $gt, $gte, $lt, $lte, $in, $contains
  example: { "price": { "$gt": 1000 }, "name": { "$contains": "BTC" } }

returns: array
```

### 3.8 mergeArrays

```
Merges multiple arrays into one, optionally joining on a key field.

params:
  arrays:  string[]  (required — list of $refs to arrays in context)
  joinKey: string    (optional — if set, performs a left-join merge on this key)
  label:   string    (optional — if set, adds a { label, ...item } wrapper,
                      using the outputKey of the source array as label)

returns: array
```

### 3.9 computeStats

```
Computes summary statistics over a numeric field in an array.

params:
  data:  array   (required)
  field: string  (required — field path to compute over)
  ops:   string[] (required — any of: "avg", "sum", "min", "max", "last", "first", "count")

returns: object — { avg, sum, min, max, last, first, count } (only requested ops)
```

## 5. Skill Chain Executor

**File:** `runtime/executor.js`

### 5.1 Entry Point

```typescript
async function executeSkillChain(
  manifest: WidgetManifest,
  registry: SkillRegistry,
  cache: Cache
): Promise<any>
```

### 5.2 Variable Resolution ($refs)

Before executing each step, the executor resolves `$ref` strings in params:

- `"$outputKey"` → replaced with the full value of `context[outputKey]`
- `"$outputKey.path.to.field"` → resolved via path navigation
- Non-string values are passed through unchanged
- Resolution is deep (recurses into nested objects and arrays)

**Implementation:** Do NOT use `JSON.stringify` + regex replace. Use a recursive object walker that checks string values for `$` prefix. This handles nested refs correctly and avoids double-encoding.

### 5.3 Execution Flow

```
for each step in manifest.skillChain (ordered by step number):
  1. resolveVariables(step.params, context)
  2. skill = registry[step.skill]
  3. validate params against skill schema (throw on missing required)
  4. result = await skill.execute(resolvedParams)
  5. context[step.outputKey] = result
  6. emit progress event to Swift bridge

return context[manifest.returns]
```

### 5.4 Error Handling

- Step failure: catch, emit `{ type: "stepError", step, skill, error }` to bridge, rethrow
- Network timeout: 10s per fetchUrl call, then throw `TimeoutError`
- Parse failure: emit error with the raw input truncated to 500 chars for debugging
- Fatal: executor catches top-level, emits `{ type: "error" }` to bridge with message

### 5.5 Caching

```typescript
interface CacheEntry {
  data: any
  fetchedAt: number   // unix ms
  ttl: number         // seconds
}
```

- Cache key: `sha256(manifest.id + JSON.stringify(manifest.skillChain))`
- Before execution: check cache. If hit and not expired, skip execution and return cached data.
- After execution: store result with manifest.ttl
- Storage: in-memory Map in JS runtime (no localStorage — not available). Swift side may optionally persist to disk via bridge message `{ type: "cacheWrite", key, value, ttl }`.
- TTL=0 means never cache.

## 6. LLM Agent Prompt

**This is the system prompt sent when the user enters a widget request.**

```
You are a widget generation agent. Given a user's request, you emit a WidgetManifest JSON object.

## Your Job
1. Determine what data the widget needs
2. Find a reliable, free, no-auth-required data source (prefer JSON APIs over HTML scraping)
3. Build a skill chain to fetch and transform that data
4. Choose the appropriate widget template type
5. Output a single valid WidgetManifest JSON object — nothing else

## Available Skills
- fetchUrl(url, method?, headers?, body?): Fetch any URL, returns raw body string
- parseHtml(html, selector, attribute?, extractText?, limit?): Extract from HTML via CSS selector
- parseJson(json, path?): Parse JSON and extract by path (supports dot, bracket, [*] wildcard)
- extractWithRegex(text, pattern, flags?, group?): Regex extraction
- parseCsv(csv, hasHeader?, delimiter?): Parse CSV to objects
- transform(data, mapping): Reshape objects (supports "literal:" and "expr:" prefixes)
- filterSort(data, filter?, sortBy?, ascending?, limit?): Filter and sort arrays
- mergeArrays(arrays, joinKey?, label?): Merge multiple arrays (arrays is a list of $refs)
- computeStats(data, field, ops): Compute avg/sum/min/max/last/first/count

## Variable References
In any param value, use "$outputKey" to reference the output of a prior step.
Path access: "$myData.items[0].price"
Wildcard: "$prices[*][1]" maps over array and returns all second elements.

## Widget Types and Their Configs
[insert §4 content here verbatim]

## Data Source Guidelines
- Prefer: CoinGecko (crypto), exchangeratesapi.io (FX), wttr.in?format=j1 (weather),
  REST Countries API (country data), open-meteo.com (weather forecast),
  api.frankfurter.app (exchange rates), numbers.dev (random facts), ISS position API
- Avoid: APIs requiring auth keys, Yahoo Finance (unstable), sites with aggressive bot detection
- When scraping HTML, prefer elements with stable IDs or semantic tags over positional selectors
- If uncertain about a URL, use a well-known public API instead of guessing

## fetchUrl Routing
All fetches go through the Swift URL allowlist handler. You do NOT need to handle CORS.
Just use the real URL in fetchUrl — the runtime handles routing.

## Output Rules
- Output ONLY the JSON object — no explanation, no markdown fences, no preamble
- All step numbers must be sequential starting at 1
- Every step that produces data used by another step must have a unique outputKey
- The "returns" field must exactly match an outputKey in the chain
- ttl: use 300 for prices, 3600 for weather, 86400 for static data, 0 for real-time

## Example Output (do not copy verbatim, reason fresh each time)
{
  "id": "a1b2c3d4-...",
  "version": "1",
  "widgetType": "lineChart",
  "config": { "title": "Bitcoin (30d)", "xField": "date", "series": [{ "field": "price", "label": "BTC/USD", "color": "#F7931A" }] },
  "skillChain": [
    { "step": 1, "skill": "fetchUrl", "params": { "url": "https://api.coingecko.com/api/v3/coins/bitcoin/market_chart?vs_currency=usd&days=30&interval=daily" }, "outputKey": "raw" },
    { "step": 2, "skill": "parseJson", "params": { "json": "$raw", "path": "prices" }, "outputKey": "prices" },
    { "step": 3, "skill": "transform", "params": { "data": "$prices", "mapping": { "date": "expr:new Date(item[0]).toLocaleDateString()", "price": "1" } }, "outputKey": "chartData" }
  ],
  "returns": "chartData",
  "ttl": 300,
  "prompt": "Show me bitcoin price for the last 30 days"
}
```

> **Note for implementors:** The `expr:` in transform for date conversion requires the executor to support a safe eval of simple JS expressions. Restrict to: arithmetic operators, `new Date(x)`, `.toLocaleDateString()`, `.toFixed(n)`, `Math.round()`. No general eval. Implement as a whitelist parser, not `eval()`.

## 7. Runtime Bundle Structure

```
runtime/
  runtime.html           # single HTML file loaded by WKWebView
  executor.js            # skill chain executor (§5)
  skills/
    registry.js          # imports and exports all skills by name
    fetchUrl.js
    parseHtml.js
    parseJson.js
    extractWithRegex.js
    parseCsv.js
    transform.js
    filterSort.js
    mergeArrays.js
    computeStats.js
  widgets/
    WidgetRenderer.jsx    # top-level renderer (§5 WidgetRenderer)
    templates/
      BarChart.jsx
      LineChart.jsx
      StatCard.jsx
      Table.jsx
      List.jsx
      PriceCard.jsx
      Text.jsx
  bridge.js              # Swift ↔ JS bridge wrapper (§1)
  cache.js               # in-memory cache (§5.5)
```

Build: bundle with esbuild into `runtime.bundle.js`. Inline into `runtime.html` as a `<script>` tag. No external network calls from the bundle itself — all external I/O is through the skills.

## 8. Swift-Side Requirements

### 8.1 URL Scheme Handler

Register a `WKURLSchemeHandler` for `widget-fetch://`. When the JS runtime calls `fetchUrl`, it sends the real URL through this handler. The handler:
1. Checks URL against allowlist (configurable, default: open)
2. Performs the actual URLSession request
3. Returns response to JS
4. Injects `Access-Control-Allow-Origin: *` header

### 8.2 LLM Call

When user submits prompt:
1. Call Claude API with the agent system prompt (§6) + user message
2. Parse response as JSON → WidgetManifest
3. Validate schema (id, version, widgetType, skillChain, returns are required)
4. On parse/validation failure: show error, do not inject into webview
5. On success: call `bridge.send("renderWidget", manifest)`

### 8.3 WKWebView Config

```swift
let config = WKWebViewConfiguration()
config.setURLSchemeHandler(WidgetFetchHandler(), forURLScheme: "widget-fetch")

// Allow JS ↔ Swift messaging
config.userContentController.add(self, name: "widgetBridge")

// Disable data store persistence (widgets are ephemeral)
config.websiteDataStore = .nonPersistent()
```

## 9. Open Questions / Future Work

These are **out of scope for v1** but should not be architectured out:

1. **User-defined allowlist** — let users add domains to the fetch allowlist
2. **Widget persistence** — save manifests to disk, reload on launch
3. **Refresh schedule** — periodic refresh based on TTL
4. **Multi-widget dashboard** — grid layout of multiple widgets
5. **Custom skills** — user-supplied JS files dropped into a `/skills/user/` directory
6. **Streaming LLM** — stream token-by-token while showing a skeleton widget
7. **Error recovery agent** — on skill chain failure, re-prompt LLM with error context to generate a corrected chain
8. **Widget editing** — tap a widget to re-prompt with its current manifest as context
