Wheel Launches Reader Mode

By Riley Chen

Wheel has added a reader mode focused on stripping away navigation, banners, and other layout noise so long-form writing is easier to scan.

The first public preview includes a dedicated overlay view, a shared extraction service, and a typography treatment tuned for sustained reading instead of dense browser chrome.

Reader mode cuts away repeated navigation and sidebar modules, but it preserves headings, images, lists, code blocks, and links so technical posts and documentation still make sense in context.

The team also moved extraction into a shared service so features like semantic indexing and agent page reading can use the same article model instead of maintaining different heuristics.

That change matters most on script-heavy pages where content selection was previously inconsistent. The new implementation captures the rendered DOM first, then runs readability on the final page state.

The goal is not just a prettier article view. It is one extraction path that stays useful everywhere else in the app.

Future work includes better metadata handling, stronger fallback behavior on marketing pages, and additional regression fixtures for docs-heavy layouts.
